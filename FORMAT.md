# PSXRC experimental format version 1

All integers are little-endian. Disc LBA 0 corresponds to MSF 00:02:00. Byte offsets are absolute file offsets. The header and index are followed by contiguous sector hunks, video groups, and audio groups in index order.

## Header and index

The 48-byte header contains the eight-byte signature `50 53 58 52 43 0d 0a 1a`, followed by ten 32-bit values. These are version, flags, sector count, track count, hunk count, video LBA count, video group count, index Adler-32, audio LBA count, and audio group count. The initial Adler-32 state is 1. Flag bit 0 enables subchannel records. Flag bit 1 enables an SBI bitmap. Flag bit 2 enables two lossless sector-filter mask bytes at the start of each decoded hunk. Flag bit 3 enables MDEC hints at the end of each video group.

| Index section | Entry |
| --- | --- |
| Track layout | Four 32-bit values for INDEX 00 LBA, INDEX 01 LBA, exclusive end LBA, and mode. Mode is raw data (0), cooked Mode 1 (1), or little-endian stereo CDDA (2). |
| Hunk records | 64-bit offset, 32-bit stored bytes, 32-bit Adler-32 of stored bytes. |
| Video group records | Same record layout as hunks. |
| Video LBA entries | 32-bit LBA and 32-bit value equal to group index × 4 + frame index. Sort entries by LBA. |
| Audio group records | Same record layout as hunks. |
| Audio LBA entries | 32-bit LBA and 32-bit value equal to group index × 36 + unit index. Sort entries by LBA. |
| SBI bitmap | If enabled, one bit per disc LBA, least significant bit first. Each set bit records a sector that the core treats as SBI-marked. |

Each hunk represents eight sectors, except for the final partial hunk. Each sector consists of 2352 bytes followed, if enabled, by one presence byte and 96 bytes of subchannel data. The presence byte uses 0 for absent and 1 for present. Cooked Mode 1 tracks use the core's virtual raw-sector layout. A stored length equal to the decoded hunk length indicates raw bytes. A shorter stored length indicates an independent Zstandard frame.

In a filtered hunk, the first mask marks Mode 2 Form 1 sectors whose 280 EDC/ECC bytes are zeroed and regenerated. The writer applies this only when the regenerated bytes match the source exactly. The second mask marks CDDA sectors. CDDA stores 16-bit deltas from the previous sample in each channel, starting at zero for each sector. Store the low bytes of all interleaved deltas followed by the high bytes.

## STR video reconstruction

Each video group begins with four 16-bit values for frame count (1–4), width, height, and a reserved zero. It starts with an IDR access unit containing parameter sets. Following frames may reference earlier frames in the group. Store one Annex B access unit per frame, in decode order.

Each access unit is preceded by a 20-byte frame record containing 8-bit quantization and BS version, a 16-bit MDEC word budget, and four 32-bit values. The 32-bit values give the access unit size, original frame byte budget, reconstructed BS size, and Adler-32 of reconstructed BS bytes.

When bit 3 is set, append one 12-byte hint per frame in decode order after the last access unit. Each hint consists of a 64-bit FNV-1a fingerprint followed by the 32-bit count of 16-bit run-length words. Hash each expanded MDEC word in little-endian byte order, including DC quantizer bits and one end-of-block word for each block. Exclude DMA padding and the BS end-of-frame marker. The video group record size and Adler-32 cover the hint trailer. A reader can ignore a hint that disagrees with the reconstructed frame and retain normal STR playback.

The hunk stores each original STR sector with the replaced frame bytes zeroed. The reader decodes the corresponding access units, re-encodes BS with the recorded quantization setting, and validates size and checksum. It overlays the frame at the original STR chunk offset, updates the duplicate header fields, and regenerates Form 1 EDC/ECC or any present Form 2 EDC.

## Audio reconstruction

Each audio group starts with four single-byte fields for kind, XA coding, sector count, and Opus packet count. Kind is CDDA (1) or XA 4-bit (2). Two 16-bit fields give the 48 kHz discard count and the resampler (0 for linear, 1 for cubic). A final 32-bit value stores Adler-32 of the reconstructed audio units. Opus packets use 20 ms frames with a 16-bit packet length followed by packet bytes. Each group represents up to 480 ms of audio with independent decode history. The discard count includes 80 ms of preroll and Opus lookahead.

Decode at 48 kHz and resample to the native rate with integer interpolation. CDDA units contain 588 stereo frames. XA units contain 4032 mono or 2016 stereo sample frames. For the Adler-32 calculation, each unit is 2352 bytes, with the 2304-byte XA sound groups padded with zeros. Insert just the sound groups into each original XA sector and update any present EDC. Each rebuilt XA sector begins with filter 0 for each channel.
